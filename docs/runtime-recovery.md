# Runtime diagnostics and failure recovery

receiver.log is initialized before Service construction. Each entry contains timestamp with timezone offset, logger, PID and thread. Fatal coordinator errors record their original exception before shutting down HTTP and exiting unsuccessfully; startup and uncaught thread exceptions are logged too. API failures include status/code, SQLite/OS errors retain a sanitized reason, and call stacks omit locals and source lines. Arbitrary exception messages are omitted to prevent comment bodies or OAuth tokens reaching logs. Known credentials, authorization schemes, webhook tokens and URL queries are redacted. Existing daily rotation and 30-day retention remain in use.

receiver-fault.log records Python faulthandler native-fault stacks where Python can write them. This is best effort, not a guarantee for OS termination, power loss or every native crash. It rolls over at startup above 2 MiB with two backups; aged rotated files are covered by retention. It does not replace receiver.log.

During actual deployment only, the existing TeamHJD-GitHubDiscord-Receiver task receives RestartInterval=PT1M and RestartCount=255. Actions, triggers, principal and ExecutionTimeLimit are preserved. The existing definition is backed up into the deployment job and restored if deployment fails. Preflight does not change task settings. Setup requires an existing SYSTEM service task with one PowerShell -File action rooted inside the service directory, and an explicit exit $LASTEXITCODE line in that launcher. Otherwise deployment stops before replacing files; do not rewrite unknown live launchers blindly.

A successful configuration is not proof of live restart recovery. Server logs, actual scheduler settings and a controlled failure/restart test must be checked separately after deployment. No deliberate production crash is performed by CI or deployment. This handles failed exits, not a hung-but-running process; intentional task stops during deployment continue to use the existing stop/start flow. The past 21:20 incident's underlying exception cannot be reconstructed from the generic old log.
