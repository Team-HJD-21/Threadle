# CI/CD status and recovery

workflow_run requested/in_progress/completed events update one github-ci message per repository, run and attempt. Receipts and terminal phase persist across restarts. Late start events cannot overwrite a terminal result. Failed PR checks still appear in the PR thread; failure heads-ups go to github-alert and respect quiet hours. Success and start never produce alert heads-ups. Both channels include the branch. Relative start timestamps are client-rendered, not a second-by-second counter; completed runs show duration from GitHub timestamps. A workflow containing both verification and deployment is displayed as CI/CD; this does not claim separate job-level CI and CD tracking.

On startup (after 10 seconds) and every minute, the GitHub App JWT client reads recent delivery metadata and asks GitHub to redeliver failed events for active connected installations/repositories. Network failures with status 0 are included. Only events not already durably received are requested. Requests are oldest-first within each scan; GitHub can deliver asynchronously, so exact cross-event ordering is not guaranteed. There are up to 30 pages per scan and 100 requests per pass. A persistent exponential cooldown prevents repeated retries during another outage. Already stored jobs resume through the normal queue. This cannot reconstruct events older than GitHub's three-day delivery retention, and legacy repository webhooks are not scanned.

Private images first use public download and existing scoped authentication. A fallback uses POST /markdown in the binding's repository context to obtain signed image URLs. Only api.github.com receives the installation token on this fallback, and CDN requests are anonymous with the existing host/redirect/size limits. Contents read permission and installation approval may be needed. HTTP permission failures are logged without tokens, URLs or signed query strings. Actual private repository download and Discord rendering require a production check; local fixtures alone do not establish that.

One image per Discord message prevents the multi-image gallery crop. Image bytes retain their aspect ratio and GIF animation; oversize sources retain the existing safe resize path. Text delivery survives attachment failures. Same-action milestone events with identical repository item, milestone, update time and sender are suppressed within 30 seconds; removing then reassigning is preserved. This is a targeted duplicate guard, not proof of the original production duplicate cause.
