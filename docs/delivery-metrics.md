# Delivery latency measurements (beta.13)

New authenticated webhook ingress records the receiver's local epoch timestamp. Dispatch copies it to every recipient's queue without resetting it, including fan-out retries. Per-delivery samples record first processing start, first acknowledged Discord message POST/PATCH and successful job completion. Non-message API writes and reads do not count as Discord delivery. Per-worker ContextVar isolation keeps independent bindings/tasks separate. Late pages/edits and retries preserve the original first timestamps.

The administrator page reads the last 200 completed, non-deferred samples with a verified ingress timestamp and valid clock ordering. It displays receiver-to-first-write median/P95 and median queue / processing-to-first-write time. Processing includes enrichment, media, network calls and retries; it is not a pure API-only timing. DND-deferred new threads are excluded from ordinary speed statistics. Admin-paused backlog and actual failure/retry delays are not silently removed. Samples without any message write, partial samples and old jobs lacking ingress timestamps do not fabricate values. A small sample count is not a stable percentile estimate.

Boundaries: these metrics begin at receipt by Threadle, not when the user clicked on GitHub. They end at Discord's acknowledged API response, not when a user's phone displays or plays its notification. Scheduled/batched heads-ups and the separate conflict monitor run outside the webhook delivery context and are not represented as end-to-end alert-channel delivery timings. This does not send probes or test notifications.

Only delivery IDs, event names, timestamps and a deferred flag are stored; no extra body, token or attachment content is collected. Completed samples and completed ingress timing records are retained for 30 days; pending work retains its receipt. Indexed retention limits local database work. Metrics storage errors during processing are logged without interrupting delivery. The page remains protected by existing administrator authentication, with no new public endpoint or external monitoring traffic.
