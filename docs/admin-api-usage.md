# 관리자 API 사용량 조회

관리자 페이지의 **API 사용량 조회** 버튼으로만 표시값을 갱신합니다. 페이지 열기·새로고침과 백그라운드 작업은 사용량 조회를 실행하지 않습니다.

- GitHub: 현재 활성 연결의 설치 ID별로 한 번씩 `/rate_limit`을 조회합니다. 일시중지된 연결도 포함하고 해제된 연결은 제외합니다. REST, GraphQL, Search의 한도·잔량·사용량·초기화 시각을 구분합니다. 같은 설치에 연결된 서버나 저장소의 한도를 합산하지 않습니다. 토큰 발급이 필요하면 기존 설치 토큰 공급자를 사용합니다.
- Discord: 평소 API 응답의 제한 헤더를 최대 64개의 요청 묶음으로 메모리에 보관합니다. 버튼을 누르면 그 정보를 화면용 스냅샷에 복사합니다. 별도 Discord 조회 요청은 보내지 않습니다. 전체 잔량이 아니며 초기화 이후의 잔량도 추정하지 않습니다. 최근 응답 확인 시각과 관측된 전역 제한 발생 시각을 표시합니다.
- 화면 스냅샷은 `api-usage.json`에 저장해 재시작 후에도 마지막 조회 결과를 확인할 수 있습니다. 재시작 후 새 조회에는 재시작 이후 관측한 Discord 응답만 포함합니다. 실패한 GitHub 조회는 이전 숫자를 재사용하지 않고 실패로 표시합니다.
- 갱신은 관리자 인증·동일 Origin·CSRF 검증을 통과한 POST만 허용하며, 동시에 한 번만 실행합니다. GitHub 한도 조회 요청에는 5초 네트워크 타임아웃을 적용하고 별도 재시도 대기를 하지 않습니다. 새 설치 토큰 발급에는 기존 발급 경로가 적용됩니다.
- 토큰·메시지 본문·원본 URL은 수집하거나 저장하지 않습니다. 제한 헤더 수집 오류가 알림 전달을 중단하지 않습니다. GitHub 2차 제한과 Discord 전체 제한을 단일 잔량으로 표시하지 않습니다.

공식 참고: [GitHub Rate limit](https://docs.github.com/en/rest/rate-limit/rate-limit), [Discord Rate limits](https://docs.discord.com/developers/topics/rate-limits).
